MyVector — executive benchmark summary

Native vector search (HNSW) for MySQL, benchmarked head-to-head vs vsql_vector, pgvector & MariaDB · 2026-11-10 13:49 UTC

fair same-host · cross-engine · by version · glove 1.2M · neutral harness · x86 / cross-ISA

Bottom line: with the shipped optimizations (PR #278 + #280), MyVector's HNSW leads at matched recall on the same host and dominates at scale, benchmarked against VillageSQL's vsql_vector, pgvector, and MariaDB's native vector index on real ann-benchmarks datasets scored vs published ground truth. These are same-host, shared-box measurements with the method fully disclosed (equal cores, cache-above-index, sequential) — read a 2–3× lead as 'clearly ahead', not a precise ratio.

What we tested

  • Engines: MyVector (MySQL 8.4/9.7/26.10 component), VillageSQL vsql_vector, pgvector (Postgres 17), MariaDB 12.3 native vector index.
  • Datasets: fashion-mnist-784 (60k×784, L2), nytimes-256 (290k×256, cosine), glove-100 (1.18M×100, cosine) — ann-benchmarks HDF5, recall@10 vs the datasets' published exact neighbors.
  • Method: HNSW M=16, ef_construction=200 (where tunable); server-side query timing; recall/throughput ef_search sweeps; engine-isolated or same-host as each page states; two harnesses (MyVector's and VillageSQL's neutral one) for cross-validation.
  • Hardware: Ampere A1/A2 (arm64) for the engine comparisons; AMD EPYC & Intel Xeon (x86) via CI runners for the cross-ISA kernel validation.

Honest caveats (the unbiased part)

  • Measurement honesty: the /fair/ lead comes from a same-host, shared-box run — controlled via equal core-pinning, cache-above-index, and sequential one-at-a-time measurement, but not a dedicated quiet machine; each engine uses its own server-side-timed harness. The method is disclosed so it's reproducible; a 2–3× is 'clearly ahead', not a precise ratio. The earlier /fair/ numbers (MyVector trailing) were pre-#280 and measured under host load — this re-run supersedes them. A mid-run fairness bug (pgvector under-cached, thrashing the index) was caught and corrected before publishing.
  • Remaining engine overhead: MyVector still carries a JSON_TABLE round-trip per ANN query (~0.28 ms); it's designed out in RFC-006. MySQL's text-literal lexing is inherent and paid equally by every engine in these text-literal benchmarks.
  • MariaDB is fast on fashion-mnist but excluded from glove-100 — not omitted, but measured: its online MHNSW build did not complete within a 10 h cap at 1.18M rows. It appears on the fashion-mnist pages where its build completes.
  • Neutral-harness scope: the /village/ page deliberately shows only what one tool measures for all four engines; insert and exact-KNN live on the per-engine pages, to keep that comparison apples-to-apples.
  • x86 end-to-end numbers come from shared CI runners (indicative throughput; valid same-runner kernel A/B); a persistent dedicated x86 host for a same-host end-to-end A/B was out of scope on cost.
